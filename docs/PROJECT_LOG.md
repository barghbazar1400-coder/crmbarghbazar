## محدودیت‌ها و پذیرش

- در این مأموریت فایل‌های PHP جدید از نظر توازن پرانتز/آکولاد و رشته‌های باز بررسی شدند؛ **این بررسی جایگزین `php -l` یا اجرای تست نیست**. لازم است پیش از پذیرش، `php -l` و `php tests/sales.php` واقعاً اجرا شوند.
- اجرای فرمان انتشار روی VPS هنوز انجام نشده و وضعیت هاست تأیید نشده است.
- پیشخوان CEO/COO آمار واقعی جدول‌های موجود را نشان می‌دهد و در نبود داده به‌جای عدد صفر ساختگی «—» نمایش می‌دهد.
- دسترسی COO باید به‌طور صریح در «منابع انسانی ← نقش‌ها و دسترسی‌ها» برای نقش مشخص تخصیص داده شود. مجوز CEO غیرقابل واگذاری و ویژه مدیر کل است.
- خطا یا ناتمام‌ماندن دیتابیس CRM باید با پیام خطا و بدون نمایش آمار ساختگی مشخص شود.
- پس از انتشار، تست‌های اولویت‌دار: دسترسی مستقیم کارمند به CEO/COO، واگذاری و تغییر وضعیت وظیفه توسط COO، خصوصی‌ماندن پیام همکاران و گزارش‌های روزانه، پروژه‌های سئو با سطح مدیر/کارشناس/کارآموز، فرم‌های قبلی، صفحه‌بندی/فیلتر و نمایش در عرض‌های ۳۹۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰.

## کنترل بازطراحی وظایف کارمند (۱۴ نوامبر ۲۰۲۶)

تغییر فقط نمایش و CSS وظایف است؛ جدول، مالکیت، وضعیت‌های مجاز، endpoint و nonce و زمان‌سنج فعلی دست‌نخورده مانده‌اند. شمار وضعیت‌های صفحه تنها از ردیف‌های همان صفحه محاسبه می‌شود و با عبارت «در این صفحه» نمایش داده می‌شود؛ شمار کل از دیتای صفحه‌بندی‌شده همان API قبلی می‌آید. فرم واگذاری مدیر به `details` جمع‌شونده تبدیل شده است. برای تأیید نهایی، نمایش یک کارمند با یک/چند وظیفه، متن طولانی، وظیفه عقب‌افتاده، تسک تکمیل شده، ثبت وضعیت و بازکردن روند انجام را در موبایل و دسکتاپ بررسی کنید.

## پذیرش بازطراحی پیشخوان کار امروز (۱۴ نوامبر ۲۰۲۶)

تغییر فقط نمای `progress-summary.php` و استایل است. کوئری‌های قبلی برای زمان‌سنج فعال کارمند، گزارش روزانه، تعداد گزارش‌های در انتظار مدیر و شش رویداد آخر تیم حفظ شده‌اند؛ کارمند همچنان حق دیدن رویدادهای تیم را ندارد. قبل از انتشار یا پذیرش نهایی، نمایش با حساب مدیر/کارمند، تست وضعیت گزارش «ثبت‌نشده/پیش‌نویس/ارسال‌شده/بررسی‌شده»، زمان‌سنج فعال/غیرفعال، صف خالی، و دسکتاپ/موبایل را بررسی کنید. آزمون واقعی فقط بعد از اجرای `php -l` و فایل تست قابل گزارش است.

## رفع بازنشدن پنجره انتخاب فایل با گیره — ۱۵ نوامبر ۲۰۲۶

**اصلاح:** کنترل به `label` حاوی `input[type=file]` واقعی تغییر داده شد؛ input با CSS به اندازه کل گیره روی آن قرار گرفته و مستقیماً با کلیک سیستم‌عامل باز می‌شود. گیره و input برای **انتخاب فایل حتی قبل از انتخاب مخاطب** فعال‌اند؛ فایل‌ها در نوار پیش‌نمایش می‌مانند و برای ارسال باید مخاطب انتخاب شود. ورودی فایل صرفاً حین آپلود غیرفعال می‌شود. اگر کارمند قبلاً به هیچ‌کس پیام نداده باشد نیز می‌تواند ابتدا فایل را انتخاب کند و سپس با `@username` مخاطب را پیدا کند.

**آزمون:** CI `43713614066` موفق (PHP lint، JS syntax، آزمون گفتگو و HTTP multipart/upload). همچنین در تست واقعی Chromium روی نمونه DOM و CSS همین کنترل، رویداد native File Chooser با کلیک گیره دریافت شد. این تست **جایگزین آزمون مرورگر روی هاست واقعی نیست**.

**انتشار:** تغییرات در GitHub ثبت شده، روی سایت اصلی deploy نشده است. پس از انتشار با `bash "$HOME/.crmbarghbazar-deploy/deploy.sh"`، صفحه پیام‌ها و مسیر انتخاب فایل با گفتگو و بدون گفتگو در Chrome/Edge باید بررسی شود.
